### 11/7 · 挑战关专属能力：空中主动改重力（已实现）

**来由**：陶毅 11/7 提议「方向键 + 空格改变重力方向，落地前不能再改」，
目的是让重力从"地形机关"变成"操作的一部分"。负责人决定**先只在挑战关 0 独立生效**，不动四关。

**操作规则**（陶毅照这个测）：

| 状态 | 操作 | 结果 |
|---|---|---|
| **站在地上** | 按空格 | 跳跃（不变） |
| **在空中** | 按住方向键 + 按 **空格** | **把重力改成该方向**（这一下空格被吃掉，不起跳） |
| **在空中** | 只按空格 | 跳预输入（不变） |

**四个方向都可用**（11/7 加 `move_up` / `move_down`）：

| 按住 | 重力变成 |
|---|---|
| `←` / `A` | 朝左 |
| `→` / `D` | 朝右 |
| `↑` / `W` | 朝上 |
| `↓` / `S` | 朝下 |

- **垂直优先于水平**：同时按住 `→` 和 `↓` 时按空格，取**朝下**
- **落地即刷新**：脚一沾地就重新获得一次改重力的机会
- **重力区优先级最高**：区里改重力不生效；**出区后**玩家设定的方向继续生效

### 11/7 触发方式的两轮反复（看完再改，别重复劳动）

**方案 A（现在用的）：空中「方向 + 空格」**

陶毅最初提的就是这个，实现最简单，不需要新按键。

**已知问题**：平台跳跃里**按住方向键是常态**（跑动时一直按着），所以「方向键按着」
不能表达"我想改重力"。实际后果：

- 按住右跑 → 跳 → 连按空格想再跳 → **意外改重力**
- 按住右跑 → 跳 → 落地前按空格做跳预输入 → **意外改重力**

**方案 B（试过，已放弃）：专用键 `Shift`**

11/7 曾改成「按住方向 + 按 Shift」，理论上是干净的——多按一个键才是明确意图，零误触。

**但负责人实机反馈「手感别扭」**：左手在方向键上，要够到 Shift 跨度太大。
方案 B 已完整回退，`gravity_shift` action 也已从 `project.godot` 删除。

**结论：回到方案 A。** 两个方案各有代价：

| 方案 | 问题 |
|---|---|
| A（方向+空格） | 与跑跳操作冲突，会误触 |
| B（方向+Shift） | 零误触，但键位别扭，手够不着 |

**如果将来还要解决这个冲突**，方向应该是**重新设计触发方式**，
而不是再换键位——换键位只是把别扭感转嫁给玩家。可考虑：

- **方向键「新按下」才算**：一直按住的不算，只有刚按下的方向才触发
- **空中松手再按**：必须先松开方向键，再重新按下

这两个都不需要新按键，且能区分"一直按着"和"有意识按下"。

**为什么只给第 5 关和挑战关开**

前四关的谜题设计**全部依赖**「重力只能由重力区改变」。比如教学关右侧那个
「10 格宽的坑，跳不过去，只能靠区」，玩家一旦能自己改重力就直接飞过去了，
那些关的难度与谜题会同时失效。

能力由关卡授权，不是全局开关：

- 第 5 关：`game.gd` 判账「是不是最后一关」后调 `player.enable_gravity_shift()`
- 挑战关：`challenge_level.gd` 调
- 前四关：不调用，能力保持关闭

**实现**（都在 `player.gd`，默认关闭所以前四关不受影响）：

- 开关：`_gravity_shift_enabled`，由关卡调 `player.enable_gravity_shift()` 打开
- 状态：`_shifted_gravity`（玩家设定的方向，ZERO = 没改过）、
  `_gravity_shift_used`（本次滞空是否用过，落地清零）
- 方向读取：`_shift_direction_from_input()`，先看 `move_up`/`move_down` 再看左右
- 重力汇总多了一条来源：没有重力区时用 `_shifted_gravity`，有区时区优先
- 转向动画、音效、`up_direction` 全部复用现有重力区那套逻辑，没有另写一份

### 11/8 · 转场用了自定义 shader（**破了 `AGENTS.md` 的「禁止自定义 shader」**）

**来由**：风扇在 `feat/ui-transition` 分支做了像素块横扫转场
（`autoload/transition.gdshader` + `autoload/transition.gd` + `transition.tscn`）。
效果是黑幕被切成像素块、扫过时逐块盖住画面，切场景与死亡重生都在黑幕全黑时才发生。

**为什么它是破例**：`AGENTS.md` 明确写了「禁止自定义 shader、后处理、视差多层背景、
粒子系统做核心表现」。这个转场用了一个 `canvas_item` shader 做逐块遮罩，
属于「自定义 shader 做核心表现」——转场是每次切场景、每次死亡重生都会走的流程。

**为什么还是合了**：这是全队唯一的转场实现，且效果确实好；
自己用代码重写一份逐块遮罩，复杂度不比 shader 低（要自己算每个块的随机错位与羽化）。
在一个 8 天周期里，为「不用 shader」重写一套核心表现不划算。

**风险与处置**：
- Web 导出时 shader 需要被正确编译，Compatibility 渲染器支持 `canvas_item` shader，
  11/8 出包验证过 Windows 版正常；**Web 版还没验证**。
- 将来若有人按 `AGENTS.md` 的规范「清理」代码，可能会把这个 shader 当违规删掉，
  所以在这里**显式登记**：这是**有意保留的破例**，不是漏网之鱼。

**如果将来必须去掉**：把逐块遮罩改成用 `ColorRect` 拼格子（每帧更新格子的 `visible`），
效果会退化（没有羽化），但能过「无 shader」的规范。

### 11/8 · 主菜单特效的三层叠加（记录一下，免得以后重复造轮子）

主菜单现在有三层各自独立的特效，职责不重叠：

| 层 | 脚本 | 受方向键影响 | 说明 |
|---|---|---|---|
| 石粒 | `Scripts/ui/menu_gravity_fx.gd` | ✅ | 90 颗白方块，流向随方向键改变 |
| 重力场辉光 | `Scripts/ui/menu_gravity_field.gd` | ✅ | **继承** `gravity_zone_visuals.gd`，只画出口辉光 |
| 四边呼吸灯 | `Scripts/ui/menu_frame_glow.gd` | ❌ | 绕四边顺时针流动，光带宽 1/3 屏高 |

**为什么重力场辉光用「继承」而不是「另写一套」或「实例化再调用」**：
- 另写一套 → 两套效果迟早跑偏
- 实例化 `gravity_zone_visuals.gd` 再 `call("_draw_exit_glow")` → 那是**它自己**的
  绘制上下文，画不到本节点上来（`_draw` 必须在节点自己的 canvas item 里画）
- **继承**则能在本节点的上下文里直接调父类的画法，辉光位置才正确

为此给父类加了一个 `set_glow_scale()`（默认 1.0，**不改变关卡里的现有表现**）。

**踩过的坑**：晶核光斑（多层同心圆叠出的柔光）试过两次都失败——
第一次太大（按短边比例算半径，主菜单 640×360 短边 360，算出 20px+ 的光斑，
就是文档第六节说的「一串白灯泡」）；第二次运动逻辑是**随机游走**
（`t = t0 + sin(...) * delta` 累加），表现为忽快忽慢的怪感。
改成「围绕基准点的椭圆游走」（两个方向用不同频率的 sin，位置是**像素级基准 + 偏移**，
不做 0..1 比例反算）才顺滑。**负责人最终决定不要晶核，11/8 已整体移除。**

### 11/8 · 编辑器开着的时候不要改场景文件（**血泪教训**）

**现象**：11/8 上午把提示 Label 直接写进 `level_4.tscn` 的节点里，
生成完不到一分钟，**Godot 编辑器一保存就把属性全覆盖了**：
位置改成别的值、字号被重算、**编辑器不认识的节点直接被丢弃**。

**为什么会这样**：编辑器读场景 → 在内存里重算属性 → 保存时写回整个文件。
它不知道脚本动态创建的节点，也不保留它不认识的属性。

**结论**：
- 场景文件里**只摆编辑器能安全往返的静态节点**
- 运行时才需要的东西（提示框、动态 UI）**用脚本创建**，场景里只挂一个空节点 + 脚本引用
- 11/8 的第 5 关改重力示意图就是这么做的（`Scripts/level/level_shift_hint.gd`）

### 11/8 · 终点不要在共享场景里绑美术

**而且这个拱门图块本来就在图块层里**（美术在 `Terrain`/`Deco` 的 `atlas(8,1)`、`atlas(8,2)` 摆的），

- `level_goal.tscn` 保持**纯触发器**，不含任何图形
