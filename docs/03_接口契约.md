# 03 · 接口契约

> **先定接口，再各自开工。** 三个人并行最容易死在"我以为你会给我这个函数"。
> 所有脚本统一 `namespace FlickCut`。

## 模块与调用关系

| 接口 / 脚本 | 维护人 | 暴露什么 | 谁调用 |
|---|---|---|---|
| `GameFlow`（状态机 + 唯一改时间缩放的地方） | 珈百璃 | `State{Boot,Playing,LevelUp,Paused,Result}`、`TimeScale`、`StartRun()`、`EndRun()` | 所有人 |
| `PlayerController` | 珈百璃 | `IsCharging`、`ChargeProgress(0–1)`、`AimDirection`、`Position` | 叶一谦、落叶归粥 |
| `ChargeController` | 珈百璃 | `BeginCharge()`、`CancelCharge()`、`Release()`、当前段位 | 内部 + HUD |
| `SlashSystem` | 珈百璃 | `Execute(start, dir, length, width, damage) → List<Enemy>` | 珈百璃 |
| `EnemyManager` + `IDamageable` | 叶一谦 | `Spawn()`、`TakeDamage(dmg, dir)`、`OnDeath` 事件 | 珈百璃 |
| `UpgradeManager` | 叶一谦 | `AddXP(int)`、`PendingLevels`、`Choose(int index)` | 珈百璃、UI |
| `HUD` | 落叶归粥（代码珈百璃给） | `SetHP(float)`、`SetTime(float)`、`SetLevel(int)`、`SetXP(float01)` | 叶一谦 |

## 三条硬规则

1. **只有 `GameFlow` 能改 `Time.timeScale`。** 蓄力慢放、顿帧、暂停全走它。三个人各自改时间缩放 = 手感永远调不准。
2. **`IDamageable` 只有 `TakeDamage` 一个入口**，谁都不能直接扣血。
3. **跨模块通信优先用事件**，不用 `FindObjectOfType`（Unity 6 已废弃，用 `FindFirstObjectByType`，但能不用就不用）。

## 升级弹窗时机（已踩过坑，别再退回旧写法）

浏览器原型阶段的 F-05 缺陷：满经验同帧弹窗 + `cancelCharge()` 把玩家蓄的力作废 + 卡片无保护期导致误选。
Unity 版必须保留这三条保护：

- 满经验先排队，**没在蓄力 + 距上次切割 > 350ms + 距上次命中 > 250ms** 才弹
- 待弹超过 **1.6 秒强制弹**（防止玩家长按导致永不升级）
- 卡片有 **300ms 保护期**，连续升级**隔 250ms** 再开第二窗
