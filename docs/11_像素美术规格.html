GRAVSWITCH · 像素美术规格

重力主题 2D 平台跳跃解谜 · Godot 4.7.2 · 8 天实训项目 · 这份看完就能开工

一、三句话定调

主题是地心间隙里的山洞。这个主题成立，而且是 8 天里最省钱的选择。但有三条必须先说清。

1. 做「亮的洞穴」，不做「暗的洞穴」

洞穴天然让人想到黑暗，但 2D 像素做光照（点光源、暗角、雾气）成本极高，而且会直接破坏玩法——玩家必须一眼看清重力区往哪个方向。所以纵深靠三档色调分层：近景亮、中景中、远景暗。不画光。

2. 做「色块洞穴」，不做「写实岩石」

岩石纹理是最容易画成墙纸的东西：拼十格就看出重复。地形只用 6 种 tile，靠轮廓不齐 + 三档明度区分，不靠纹理细节。这样既省钱又好看。

3. 颜色只编码三件事

紫 = 重力区，橙 = 危险，青 = 你。方向靠箭头，不靠颜色。四向各配一色看起来聪明，实际是让玩家记四个含义、让你们多画四套素材。

二、画布与尺寸

项值说明
逻辑分辨率640 × 360一屏 20 × 11 格
tile 尺寸32 × 32 px所有关卡、机关、地形都按这个拼
角色画布32 × 32 px方便对齐网格、在 Godot 里切帧
角色实际像素20 × 28 px画在 32×32 画布里，水平居中、底部贴齐
角色碰撞盒20 × 28 px与像素区重合，不要画超出画布
一关尺寸20 × 11 格= 640 × 352 px

角色在屏幕上有多大：1080p 全屏是 3 倍整数缩放，20 像素宽会变成 60 像素。手脚和朝向都看得清，不需要画到 48px。

三、调色板

不是全锁死的。真正不能动的是 5 个编码玩法信息的颜色，其余 7 个你们自己调，改完在表里写新值就行。

锁死（5 个 · 动之前群里说一声）

色色值用途为什么不能动
#2E2530中景岩壁 / 地形内部三档明度里的一档，动了纵深关系就散
#4A3B45近景岩壁（能站的地面与天花板）同上，而且这是玩家判断「能不能站」的依据
#7FE8FF玩家全场唯一的青，混了就找不到自己

#FF8A3D危险（尖刺）橙只给「会死的东西」，别处不许用橙

加色规则

可以加。新色接着往下排（P13、P14…），写进上表并注明用在哪，然后过这一条：

把画面转成灰度，玩家、重力区、尖刺三样必须还能分开。分得开就加，分不开就不许加。

这条不是审美要求，是玩法要求：玩家靠颜色判断「这里有重力」「这个会死」。灰度分不开，色盲玩家分不出，路演投影仪上也会糊成一片。

底色已改过：从 #0B0E14 换成 #100D14。原来那个是冷蓝黑，配太空题材用的；现在是地心洞穴，岩壁是暖紫棕，冷底会把画面压灰，而且玩家是青色，跟冷底同色系会融进去。换成暖紫黑之后，青色玩家在暗处是跳出来的。

四、角色

20 × 28，放大 4 倍看

只用 3 个颜色：主色 #7FE8FF、暗部 #3A8FA8（同时当描边）、一处高光 #D6F7FF。

体积靠形状和描边出，不靠渐变——12 色做不了渐变，硬做会脏。

外轮廓必须有 1px 深色描边，否则在暗背景里会融进去。最省事的做法：先铺一层暗色底，再用主色往里缩 1px 画。

动作帧数优先级
idle 站立2必须有
run 跑4必须有，玩家看得最多的一帧
jump 上升1必须有
fall 下落1必须有
die 死亡3有余力再画，没有就用闪白代替
  • 共 11 帧。run 的 4 帧是重点，其他都可以糙。
  • sprite sheet 横排成一行，每帧 32×32，按上面顺序从左到右。Godot 里一个 Sprite2D 填 hframes = 11 就能切。
  • 只画朝右，朝左在引擎里用 flip_h 翻转，不要画两套。

五、地形

关内局部（8 格宽）。岩壁边缘不齐、有抠块和受光短线，但仍是色块，没有纹理
#tile说明
0空不画，留透明
1实心砖 · 上表面2px 高光顶边，玩家站这面
2实心砖 · 下表面2px 高光底边，重力翻过来后玩家站这面
3实心砖 · 侧面无高光，洞壁
4实心砖 · 内部无高光，纯 #2E2530，用于填厚
5单向平台只画上半格，薄，下方透明
第 2 种（下表面）必须有，而且要和第 1 种一样明显。我们的玩法会让玩家倒着站天花板。天花板如果看起来跟内部砖一样平，玩家不知道自己能站——这是整套规格里唯一一个「不做就会让玩法失效」的点。

tileset 图布局：一张横排 PNG，每格 32×32，间距 0，不要留边距。Godot 建 TileSet 时填纹理区域 32×32、分离值全 0。

六、重力区与危险

重力区不画纹理

它是半透明色块 + 白色箭头，在 Godot 里用 ColorRect 加 #9B7FD4、透明度约 0.24 就能做，不需要图。面板上你们要交的只有四种箭头图标（16×16 或 24×24）：上、右、下、左，颜色 #D9C7FF，一张横排 sheet。

边框用像素虚线（8px 实 5px 空），四角各一个小方块标记。不要做成实心大方块——实心会盖掉地形，玩家看不出这块区域贴着什么。

尖刺

32×32 一格，三角朝上，只画一个方向，布置时旋转。底部必须有基座（3–4px 深色条），否则看起来像浮在地面上。尖端加 #FFF2E0 白边，暗处才看得见轮廓。

可动平台

直接复用 tile 的上表面和下表面，不单独做素材。

七、命名与导出

前缀用于示例
spr_有动画的东西spr_player.png · spr_spike.png
tile_TileSet 图tile_cave.png
bg_背景（可平铺）bg_cave.png
ui_界面元素ui_button.png
icon_图标icon_arrow_up.png

全小写下划线，不加版本号（_v2、_final、_new 一律不许）。改了就覆盖，历史在 Git 里。

导出：PNG、透明背景、1:1 原始像素、不加锐化不加抗锯齿不加滤镜、透明区必须是真透明（不要填白）。不要用 JPG——JPG 会把边缘糊成噪点。

八、UI 与字体（11/2 用，但现在就要知道）

Godot 4 的内置字体不含中文字形。界面上写「继续」「通关」会显示成一排方框 □□□。这不是编码问题，不是你写错了，是那个字体文件里根本没有这些字。

所以现在就要准备：往仓库 Art/Fonts/ 放一个开源中文字体，然后在 项目设置 → GUI → Theme → Default Font 指定它。

字体体积说明
得意黑 Smiley Sans约 4 MB推荐。开源可商用，倾斜感强，做标题和 UI 都好看
思源黑体 SC Regular约 8 MB最稳，字形规矩，不出错

不要用系统字体路径（C:/Windows/Fonts/msyh.ttc 这种）。换一台机器就找不到，六个人里五个人的界面会变方框。

字号只允许四档：16 / 24 / 32 / 48。不用 12——中文在 12px 下笔画粘连认不出来。也不用 13、17、20 这种：非整数倍缩放会糊。

元素位置字号
关卡号（01 / 02…）左上角 (16, 12)16
中央提示（如「按住 ↓ 改变重力」）屏幕中央偏下24
死亡 / 通关大字屏幕正中48
按钮（开始、重玩、下一关）屏幕中央竖排16，按钮最小 120 × 32

不做的：血条（一碰就死，没有血量）、计时、小地图、设置菜单、音量滑块。一屏一关的游戏不需要这些。

这不是拖延，是省返工。平台游戏最经典的浪费就是美术按「看着能跳过去」画了整套地形，程序跑不过去，全部重画。

十、三条禁令

  1. 加颜色要登记。新色接着 P13 排下去，写进第三节的表并注明用在哪，再过一次灰度判据。不登记就画，下一关没人知道那个色是什么。
  2. 不许画超出画布的内容。角色在 32×32 里画，超出的部分在 Godot 里会被切掉，看起来像 bug。
  3. 不许画「暗洞穴」。不画光源、不画阴影渐变、不画雾。纵深靠三档明度，不靠光。
