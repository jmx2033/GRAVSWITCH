# 01 重力 · 核心机制与切片

> 主题：重力（社团官方公布）。引擎：Godot 4.7.2 + GDScript。
> 本文件取代 `03_接口契约.md` 与 `04_数值表.md`。
> 概念来源：10/31 群内提案「玩家操控星球，敌人是小行星，引入 2D 重力系统，让小行星被玩家牵引」。

## 一、一句话

> 你是一颗会变重的星球。按住，你的质量暴涨，附近的小行星被拽弯；但你也变得又重又难躲，被自己拽来的东西撞上照样掉血。

**设计假设**：新玩家在 40 秒内会自己发现「不加重能活，但场上越来越挤」，并且在一局里至少主动松开一次来躲。

如果只观察到「一直按住」或「一直不按」，说明取舍没做出来，机制是假的。

### 为什么全篇叫「重力」，不叫「引力」

主题公告上印的两个字是**重力**。这一条要守住，怎么守写在下面。

**物理上它们是同一个东西**：重力就是引力在地表附近的表现，英文都叫 gravity。所以「重力把小行星拉过来」不构成事实错误，不用怕被挑刺。

**但中文语感里是分开的**，这才是要处理的问题：

| 词 | 一听脑子里出现什么 |
|---|---|
| 重力 | 下坠、重量、沉、砸、井、楼层 |
| 引力 | 星际、黑洞、轨道、拉扯、科幻 |

评委是别的队的开发者，看到「重力」想到的是左边那列。所以**动作、文案、UI、代码命名一律用重力**，尤其别在 HUD 上写「引力圈」三个字。

**但只改词不够，还得让人感觉到重量。**三层做法，成本递增：

| 层 | 做法 | 成本 | 做不做 |
|---|---|---|---|
| 一｜词 | 统一改称重力；玩家按住的动作用「**加重**」，不说「开重力场」 | 0（现在代码还是 0 行） | **做** |
| 二｜体感 | 越重，玩家自己被压得越扁、移速越慢（数值已有），画面轻微下压 | 一个缩放动画 | **做** |
| 三｜世界 | 所有小行星与碎片朝同一方向持续加速（世界自己也有重力），飞入轨迹变成抛物线 | 每帧一行，但要重调平衡 | **会上定** |

第三层一旦做，「重力」就从「你的一个技能」变成「这个世界的物理」，主题扣得最死，预测虚线也有了更强的存在理由——抛物线比直线更需要提前看。代价是难度要重调，所以留到会上拍。

**叙述上的统一：玩家不是「开了一个场」，是「自己变重了」。**效果一样，但「我变重了所以拉得动东西」比「我开了一个引力场」直觉得多，而且直接落在「重量」这个词上。

## 二、为什么原提案要改三处

原提案「小行星被玩家牵引」方向对，但直接做会有三个洞：

| 洞 | 现象 | 修法 |
|---|---|---|
| 重力是常开的属性，不是动作 | 玩家按不按都一样，实际只是站着 | 改成**按住才加重**，且**圈就是危险圈** |
| 伤害只进不出 | 撞玩家掉血，最优解是躲远，重力纯负担 | 加两个收益：**互撞碎**、**甩出去砸人** |
| 轨道不可读 | 连续积分看不出它会飞哪，全靠运气 | **提前 0.5 秒的预测虚线** |

## 三、核心循环（约 6 秒一轮）

小行星从边缘飞入 → 判断「现在加不加、加多重」 → 拉成轨道让它们互撞 / 或松手把正在绕的那颗甩出去 → 场上变空 → 下一波更密

三种结局（同一个重力圈）：

| 你的选择 | 结果 |
|---|---|
| 不加 | 它撞墙反弹，永远留在场上。安全，但场越来越挤 |
| 加重，吸一颗 | 它弯向你，**撞上掉 1 格血** |
| 加重，同时吸两颗 | 它们互相撞碎，**场上清空** |

## 四、三条必须一起成立的判定

1. **重力场半径随蓄力增长，且这个圈同时是吸引范围与危险范围**
   一物两用。玩家看一眼就知道为什么加得越久越危险——不需要教程。
2. **松手保留切向速度 ×1.6 甩出**
   这是唯一能打到远处的手段，也是「绕转」变成有意义操作的关键。
3. **预测轨道虚线，提前 0.5 秒**
   没有它，玩家只能靠运气，学不到任何东西，试玩时会说「不知道为什么会撞上」。

## 五、数值初稿（全部放进一个 `config.gd`，改数值不用改逻辑）

| 项 | 值 | 说明 |
|---|---|---|
| 逻辑分辨率 | 1600 × 900 | 窗口 1280×720 等比缩放 |
| 玩家半径 / 移速 | 28 px / 90 px/s | 慢是刻意的，大质量 |
| 蓄力时移速 | ×0.4 | 加重时走不快，躲不开 |
| 重力场半径 | 120 → 320 px | 蓄满 1.2 秒 |
| 重力加速度 | 600 → 1400 px/s² | 用 `a = A×(1 − r/R)`，**不要用 1/r²**（会出奇点，近处直接飞出去） |
| 小行星半径 / 初速 | 8–16 px / 180–260 px/s | 沿随机方向直线飞入 |
| 撞墙反弹 | 弹性 0.9 | **永不消失**，这是压力来源 |
| 互撞判定 | 距离 < 两半径之和 且 相对速度 > 80 | 双方碎 |
| 玩家受击 | 掉 1 格，0.8 秒无敌 | 共 3 格 |
| 甩出 | 切向速度 ×1.6，0.4 秒内不受重力 | 松手触发 |
| 一局 | 180 秒 | |
| 生成间隔 | 2.2 秒 → 0.9 秒 | 随局内时间线性递减 |

**为什么要「永不消失」**：小行星撞墙反弹、留在场上，场才会越来越挤。这是玩家必须加重的唯一理由。如果它们飞出屏幕就消失，玩家会全程不加重，机制直接失效。

## 六、状态与输入

- 状态：`Ready → Playing → Dead → Result → (重开回 Ready)`
- 输入只有三个：`WASD/方向键` 移动、`按住空格或鼠标左键` 加重、`Esc` 暂停
- **没有攻击键、没有冲刺、没有升级**。多一个动词，这个机制就不是它了

## 七、切片范围（按 45 小时/人的真实工时砍过）

### P0 · 11/4 24:00 前必须全绿（能玩的最小闭环）

1. 玩家星球，WASD 缓慢移动
2. 按住加重，半径随蓄力增长
3. 小行星从边缘直线飞入
4. 重力弯曲轨迹（手写积分，不用物理引擎）
5. 撞到玩家掉血，3 格，受击无敌
6. 死亡结算 + 一键重开

### P1 · 11/7 22:00 冻结前（让机制成立）

7. 预测轨道虚线（0.5 秒）
8. 两颗小行星互撞碎
9. 松手甩出（切向 ×1.6）
10. HUD：血量 / 时间 / **场上小行星数**（这个数字本身就是压力表）

### 不做（写死，会上不讨论）

第二种敌人、Boss、升级与卡池、局外成长、多关卡、剧情、排行榜、联机、音效正式制作、手柄支持。

> 启动会原话：**「牢记贪多嚼不烂」**。上面这 10 项已经是按 45 小时砍过一轮的结果。

## 八、任务拆分（对应 6 人 × 45 小时）

| # | 任务 | 主要产出 | 依赖 |
|---|---|---|---|
| T1 | 玩家移动 + 相机 | `player.gd` | 无 |
| T2 | 重力场 + 蓄力 | `gravity_field.gd` | T1 |
| T3 | 小行星生成与飞行 | `asteroid.gd`、`spawner.gd` | 无 |
| T4 | 被重力弯曲（手写积分） | 并入 T2 | T2、T3 |
| T5 | 预测轨道虚线 | `_draw()` 画线 | T4 |
| T6 | 碰撞与血量 | `damage.gd` | T3 |
| T7 | 互撞碎 | 并入 T6 | T6 |
| T8 | 甩出 | 并入 T2 | T2 |
| T9 | HUD / 结算 / 重开 | `hud.tscn`、`result.tscn` | T6 |
| T10 | 出包 + 上传 + 链接 | 导出预设 | 全部 |

T2 与 T4 必须同一个人做完——重力的手感全在这两个里，拆开必然两边都调不出来。

## 九、试玩阈值（5 人，各 3 局）

只观察，不解释。记录：第一次加重在第几秒、一局里开关次数、死亡原因。

| 门槛 | 阈值 |
|---|---|
| 40 秒内主动加重 | ≥ 3/5 人 |
| 一局内主动松开、回到轻来躲 | ≥ 2/5 人 |
| 能说出「开大了会害死自己」 | ≥ 2/5 人 |
| 「不知道该干什么」 | 0 人超过 1 次 |

第三条是这套设计成立与否的唯一证据。观察不到，先改数值（把重力场半径调大、把移速继续降），再谈加内容。

## 十、最大风险

**「一直按住」把游戏玩成挂机。**如果玩家发现按住不放就能让所有东西堵在自己的重力圈里互撞，游戏就结束了。

两道防线：蓄力时移速 ×0.4（躲不掉）、圈内圈外饱和（吸得越多，撞你的概率越高）。这两条调不出来，机制就是假的。
