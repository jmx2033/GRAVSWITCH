# 像素美术规格

> 给美术 A（风扇）、美术 B（三尺）
> 这份看完就能开工。尺寸、色值、命名、导出，全部照抄，不要自己发挥。

## 一、四句话定调

主题是**地心洞穴的间隙**——地壳深处裂开的一条缝，上下都是岩壁。这个主题成立，而且是 8 天里最省钱的选择。但有四条必须先说清：

**1. 做「亮的洞穴」，不做「暗的洞穴」。**
洞穴天然让人想到黑暗，但 2D 像素做光照（`Light2D`、`CanvasModulate`、点光源）成本极高，而且会直接破坏玩法——玩家必须一眼看清磁场往哪个方向。所以用**色调分层**造纵深：近景亮、中景中、远景暗。不画光。

**2. 做「色块洞穴」，不做「写实岩石」，而且是 Q 版。**
岩石纹理是最容易画成墙纸的东西：拼十格就看出重复。只用 6 种 tile，靠**轮廓不齐 + 三档明度 + 切角**区分，不靠纹理细节。Q 版指的是比例（2 头身）和圆角，不是细节量——**Q 版会把画面变得更简单，不是更复杂。**

**3. 颜色只编码三件事，不编码第四件。**
紫 = 磁场（改重力），橙 = 危险，青 = 你。**方向靠箭头，不靠颜色。** 四向各配一色看起来聪明，实际是让玩家记四个含义、让美术多画四套素材。

**4. 全场只有磁场里的石粒会动，其他任何东西都不许动。**
世界是死的，磁场是活的。这一条同时解决两个问题：一眼能看出「哪块地方特殊」，以及不会因为满屏都在动而看不清方位。

## 二、画布与尺寸

| 项 | 值 | 说明 |
|---|---|---|
| 逻辑分辨率 | **640 × 360** | 一屏 20 × 11 格 |
| tile 尺寸 | **32 × 32 px** | 所有关卡、机关、地形都按这个拼 |
| 角色画布 | **32 × 32 px** | 方便对齐网格和在 Godot 里切帧 |
| 角色实际像素 | **20 × 28 px** | 画在 32×32 画布里，水平居中、底部贴齐（上方留 4px 余量放头顶/跳跃拉伸） |
| 角色碰撞盒 | 20 × 28 px | 与角色实际像素区重合，不要画超出画布 |
| 一关尺寸 | 20 × 11 格 = 640 × 352 px | 下方留 8px 给地板厚度余量 |

**角色在屏幕上有多大**：1080p 全屏是 3 倍整数缩放，20 像素宽会变成 60 像素。正常人一眼能看清手脚和朝向，不需要画到 48px。

### 加色规则：可以加，但要过一条判据

新色接着排（P13、P14…），写进上表并注明用在哪，然后过这一条：

> **把画面转成灰度，玩家、重力区、尖刺三样必须还能分开。** 分得开就加，分不开就不许加。

这条不是审美要求，是玩法要求：玩家靠颜色判断「这里有重力」「这个会死」。灰度分不开，色盲玩家分不出，路演投影仪上也会糊成一片。

**底色为什么从 `#0B0E14` 改成 `#100D14`**：原来那个是冷蓝黑，配太空题材用的；现在是地心洞穴，岩壁是暖紫棕，冷底会把画面压灰，而且玩家是青色，跟冷底同色系会融进去。换成暖紫黑之后，青色玩家在暗处是跳出来的。

## 四、角色（`spr_player.png`）· 青色宝石小人

**玩家是什么（11/1 定）**：一块**被磁化了、会走路会跳的青色宝石小人**。

这一句同时解决了两件事：形状有了，机制也解释了——**磁性在他身上，不用再给他挂任何道具**。他进磁场就被拉走，是因为他自己就是那块磁石。原来设想的「小人身上挂一块 3×2 小磁石」取消。

**宝石感怎么画**：20×28 里放不下三层切面，切多了就是噪点。

- **亮暗面 + 一条对角线**：亮面压左上（实测 `#7BFFD1` / `#E5FFF3`），暗面压右下（实测 `#2C6195`），头和身**各一条**，不描第二层边、不做渐变。**色值以交付的 `spr_player.png` 实际用色为准**（见第三节实测表）
- 光**永远从左上来**。这个角色倒过来站天花板时**不改亮暗**——改了等于多画一套图，而且玩家会以为人翻面了
- 参考过一张正面 3/4 视角的图，只能借气质，不能借画法：我们的玩家全程是侧面，而且那张图 800px 高，切面和星星到 28px 全都消失，剩下只有轮廓

**Q 版 = 2 头身。** 具体到像素，照这张表画，不要自己调比例：

| 部位 | 尺寸 | 位置 |
|---|---|---|
| 头 | **16 × 14** | 水平居中（左右各留 2px），顶对齐 `y=0` |
| 身 | 14 × 12 | 头正下方，居中 |
| 腿 / 脚 | 各 4 × 4 | 底部贴 `y=28`，两脚间距 4px |
| 眼睛 | 各 **2 × 3** 竖点 | 头上半部，两眼中距 6px，朝哪边就整体偏 1px |
| 嘴巴 | **不画** | 20×28 画不下嘴，画了就是噪点 |
| 描边 | 1px，**色值以实际素材为准**（11/2 交付版是黑） | 只描角色，不描地形 |

16 + 12 = 28，正好占满角色实际像素高度；宽 20 由头（16）决定，肩比头窄 2px，看起来才 Q。

**Q 版的三个动作要点**（比画得精细重要得多，而且几乎不增加工时）：

| 动作 | 怎么做 | 效果 |
|---|---|---|
| idle 2 帧 | 整体上下移 **1px**，脚不动 | 呼吸感 |
| run 4 帧 | 身体上下颠 1px + 腿前后各 2px，**头不动** | 弹跳感；头一晃就晕 |
| jump / fall | jump 整体**拉长 1px**，fall 整体**压扁 1px** | 不用额外画帧 |
| die 3 帧 | 压扁 + 左右各弹 2px | Q 版死法要可爱，不要见血 |

**描边澄清（11/2 修订）**：角色**要** 1px 描边，**颜色以实际素材为准**——11/2 交付版用的是黑；觉得在深色底上发闷就换深青，由美术定。地形**不要**描边，靠明度差分。

**动画帧数按这个来，不要多画。**

| 动作 | 帧数 | 优先级 |
|---|---|---|
| idle（站立） | **6**（11/2 实交） | 必须有 |
| run（跑） | **8**（11/2 实交） | 必须有，这是玩家看得最多的一帧 |
| jump（上升） | 1 | 必须有 |
| fall（下落） | 1 | 必须有 |
| die（死亡） | 3 | 有剩余时间再画，没有就用闪白代替 |

**11/2 实交 14 帧**（idle 6 + run 8）；jump 1 / fall 1 / die 3 共 5 帧待补，**全齐后 19 帧**。run 的帧数最多，是重点。

**sprite sheet 布局（11/2 改）**：**两行**——第 1 行 idle 横排、第 2 行 walk 横排，每帧占 32×32 的格子，共 **8 列 × 2 行 = 256×64**；idle 只占第 1 行前 6 格，第 7、8 格留空。Godot 里填 `hframes = 8` + `vframes = 2`：**idle 播 frame 0–5，walk 播 frame 8–15**。不要做成一张张散图；后续 jump / fall / die 追加到表尾。

**朝向**：只画朝右，朝左在 Godot 里用 `flip_h` 翻转。不要画两套。

## 五、地形（`tile_cave.png`）· 切角是 Q 版的关键

**只做 6 种，多一种都不要。**

| 序号 | tile | 说明 |
|---|---|---|
| 0 | 空 | 不画，留空 |
| 1 | 实心砖 · 上表面 | 有 P05 高光顶边，玩家站这面 |
| 2 | 实心砖 · 下表面 | 有 P05 高光底边（重力翻过来后玩家站这面） |
| 3 | 实心砖 · 左右侧面 | 洞壁 |
| 4 | 实心砖 · 内部 | 无高光，纯 P04，用于填厚 |
| 5 | 单向平台 | 比砖薄，只画上半格，下方留透明 |

**关键一条**：第 2 种（下表面）必须有，而且要和第 1 种一样明显。**我们的玩法会让玩家倒着站天花板**，如果天花板看起来跟内部砖一样平，玩家不知道自己能站。

**tileset 图布局**：一张横排 PNG，每格 32×32，**间距 0，不要留边距**。Godot 的 TileSet 建的时候填 `texture_region_size = 32×32`、分离值都给 0。

**你交到哪为止**：交**这一张 `tile_cave.png`**就完事。**不用摆关、不用建 TileSet、不用配碰撞**——那些是策划和程序的活（见 `03` 第七节）。你在 Aseprite 里画完、按格切好、导出，你的地形部分就结束了。

**顺带一个版本常识**：Godot 4.7 里摆格子用的节点叫 `TileMapLayer`，不是 `TileMap`（后者已废弃）。你要是照着网上教程找 `TileMap` 会找不到，这不是你操作错了。

**Q 版化的两条，几乎不花时间但一眼能看出来：**

1. **所有「外露的角」切 2px 斜角。** 直角看起来是工程图，切角看起来是 Q 版。只切玩家能看见的那个角（顶面两端、侧面上下端），被邻居挡住的角不用切。
2. **砖面只给 3 档明度，不加第二层纹理。** 明度分档已经在上一节的表里。

**不要做的 Q 版化**：不加圆点、不加笑脸、不在砖上画小石头。32px 一格塞任何装饰都会变成噪点，而且是两个人画风分叉最快的来源。

## 六、磁场（= 文档里说的「重力区」）与危险

**先说命名，这条会直接打架**：文档和群里习惯叫「重力区」，美术表现叫**磁场**，代码和场景名**一律用 `gravity_zone`**。不要因为叫磁场就把代码名改了——CI 的提交 scope 是 `gravity`，已有脚本和场景都按这个走，改一次全队要跟着改。

**为什么用磁场表现重力**：重力看不见，磁场能画。玩家不需要理解物理，只需要知道「这块紫的地方在拽我」。磁场给了三样东西：能流动的场、能指方向的箭头、能上浮的粒子。

### 三层，只有石粒会动

**核心一句：石粒朝哪边飘，重力就朝哪边。** 玩家不看箭头也能读懂——因为它就是「有东西在往那边掉」。箭头只是保证三米外和投影仪上也能一眼看到。

| 层 | 画法 | 谁来画 | 会动吗 |
|---|---|---|---|
| 场体 | `ColorRect` + `P08`，不透明度 **0.22–0.30** | 程序 | 不动 |
| 边界 | 2px 实线 `P08` + 四角各一个 4×4 加粗角标 | 程序 | 不动 |
| **悬浮石粒** | 每 32×32 格 **3 颗**、**每个磁场最多 24 颗**，每颗 **2×2px**，`P11` 不透明度 0.55 | 程序 | **唯一会动的**：沿箭头方向匀速漂 10 px/s，出界从反方向重入 |
| 方向箭头 | 16×16，白芯 `P12` + `P09` 描边 | **美术** | 不动 |

**为什么边界不用虚线**：8 实 5 空的虚线在 640×360 上会被 3 倍整数缩放放大成一条条 24px 的长杠，看起来像在闪。改成 **2px 实线 + 四角加粗**，一样能说明「这是区域不是墙」，而且不闪。

**为什么石粒不用贴图做**：石粒必须**连续漂移**才读得出方向，3 帧贴图只能原地抖；而且每格都循环同一张图，会拼出肉眼可见的重复。石粒由程序用 `ColorRect` 生成，每颗相位错开。

### 三条硬限制

1. **石粒必须比箭头暗。** 箭头是纯 `P12` 实心 + 描边，石粒是 `P11` 且在 0.55 不透明度——一眼分得出主次。一样亮就是一片雪，方向反而读不出来。
2. **每格 3 颗、每颗 2×2，但每个磁场总数封顶 24 颗。** 教学关那块磁场是 6×9 格，按 3 颗/格算会到 162 颗——那不是碎石，是沙尘暴，整块紫场会变成一片糊。**面积越大密度越低**：小磁场（1–4 格）给 3 颗/格，大磁场按 24 颗摊开。4 颗以上/格或 3×3px 以上，看起来是沙尘不是碎石，还会跟角色撞色。
3. **场体不透明度上限 0.30。** 超过之后玩家看不出这块紫里哪面墙能站，会直接走进坑里。

### 磁场这块，美术只交一个箭头

磁场其余三层全是程序画的，美术要交的只有**一个朝上的箭头图标，16×16**：三角底宽 12px、高 10px、杆宽 4px，垂直居中。太小在 3 倍放大后读不出方向，太大就盖住地形。

四向靠 **90° 整数旋转**（像素 90° 旋转无损，任意角度才糊），引擎 `rotation_degrees` 填 0 / 90 / 180 / 270。**不要画四个。**

**尖刺**（`spr_spike.png`）：32×32 一格，三角朝向由摆放旋转解决，只画朝上一个方向。底部与地面接触处加 `P11` 白边提亮，否则在 `P04` 地面上看不出边缘。Q 版化：尖角切 1px，改「圆头三角」，一个像素的改动，气质差很多。

**可动平台**（`spr_platform.png`）：**单独一张，不许复用 tile**——长得跟砖一样，玩家要等它开始动才知道这是平台，第一次踩上去必被甩走。96×20 一张整图（3 格宽 × 16 px 厚，底下留 4 px 透明），长度和行程在 `03` 里都写死了，不用拼接。

- 主体 `#7C8FA6` 钢蓝灰，顶面 2 px 亮边 `#B4C6D8`，四角切 1 px（跟砖同一个圆角规矩）
- 顶面亮边上等距点 3 个 2×2 小方点，读起来像传送带——**这是唯一提示「它会动」的地方**
- 不画箭头、不画链条、不加光效。这两个色比地形亮一档就成立，具体值你自己调，只要不跟磁场的紫打架

（源文件自己留着，仓库里只放导出的 png）。

**导出设置**：

- 格式 **PNG**，透明背景，不要 JPG（JPG 会把边缘糊成噪点）
- **不要缩放**，按 1:1 原始像素导出
- 不要在导出时加锐化、加滤镜、加抗锯齿
- 透明区域必须是真透明，不要填白色

## 八、交期与顺序（这个顺序不能反）

| 时间 | 交什么 | 谁 |
|---|---|---|
| **10/31 今晚** | `spr_player.png` 先用纯色块代替：一个 20×28 的青色方块，能跑就行 | 谁都快 |
| **11/1 上午** | `tile_cave.png` 6 格、`spr_spike.png`、`spr_platform.png`、一个朝上的箭头图标（16×16） | 一人一半 |
| **11/1 晚上** | `spr_player.png`：**11/2 已交** idle 6 帧 + run 8 帧（两行 256×64），jump / fall / die 5 帧待补 | 风扇 |
| **11/2** | `bg_cave.png` 背景 + 主菜单与通关页 UI | 三尺 |

**那个箭头排在 11/1 上午，不能往后拖。** 教学关只有一样机关就是磁场，箭头不到位，教学关就演示不了核心机制；而且它决定四关里所有紫色区域的观感，后面三关都照着它定。

**今晚不要画正式素材。** 关卡还没画完（`docs/03_四关设计.md` 只有教学关），现在画的贴图很可能对不上实际布局。今晚只做一件事：**用色块把角色跑起来**，验证自己的导出流程能进 Godot。

**这不是拖延，是省返工。** 平台游戏最经典的浪费就是美术按「看着能跳过去」画了整套地形，程序跑不过去，全部重画。

## 九、四条禁令

1. **加颜色要登记。** 新色接着 P13 排下去，写进第三节的表并注明用在哪，再过一次灰度判据。不登记就画，下一关没人知道那个色是什么。
2. **不许画超出画布的内容。** 角色在 32×32 里画，超出部分在 Godot 里会被切掉，看起来像 bug。
3. **不许画「暗洞穴」。** 不画光源、不画阴影渐变、不画雾气。纵深靠三档明度（`P02` / `P03` / `P04`），不靠光。
4. **除了磁场里的石粒，什么都不许动。** 全游戏唯一的动态是石粒漂移。不画背景飘尘、水滴、视差、角色待机以外的环境动画。这不是省事——满屏都在动，玩家就分不清哪个动的东西在告诉他方向。

## 十、UI 与字体（11/2 才做，但现在必须知道）

**Godot 4 内置字体不含中文字形。** 界面上写「继续」「通关」会显示成一排方框（□□□）。这不是编码问题，不是你写错了，是那个字体文件里根本没有这些字。

所以现在就要准备：往仓库 `Art/fonts/` 放一个开源中文字体，然后在 `项目设置 → GUI → Theme → Default Font` 指定它。
（目录名全小写 `fonts`，跟第七节的树一致；Linux 和 GitHub Actions 上`Fonts`和`fonts`是两个不同目录，大小写写错一次就找不到字体。）

| 字体 | 体积 | 说明 |
|---|---|---|
| **得意黑 Smiley Sans** | 约 4 MB | 推荐。开源可商用，倾斜感强，做标题和 UI 都好看 |
| 思源黑体 SC Regular | 约 8 MB | 最稳，字形规矩，不出错 |

**不要用系统字体路径**（`C:/Windows/Fonts/msyh.ttc` 这种）。换一台机器就找不到，六个人里五个人的界面会变方框。

**字号只允许四档**：16 / 24 / 32 / 48。

不用 12：中文在 12px 下笔画粘连，认不出来。也不用 13、17、20 这种：640×360 的游戏做非整数倍缩放，字会糊。

**HUD 布局（都在 640×360 内）**：

| 元素 | 位置 | 字号 |
|---|---|---|
| 关卡号（`01` / `02`…） | 左上角 (16, 12) | 16 |
| 中央提示（如「按住 ↓ 改变重力」） | 屏幕中央偏下 | 24 |
| 死亡 / 通关大字 | 屏幕正中 | 48 |
| 按钮（开始、重玩、下一关） | 屏幕中央竖排 | 16，按钮最小 120 × 32 |

**不做的东西**：血条（我们是一碰就死，没有血量）、计时、小地图、设置菜单、音量滑块。一屏一关的游戏不需要这些，做了就是浪费 11/1 那个唯一整天。

## 十一、玩法与画面（这一关长什么样）

> 这一节回答三个问题：**具体玩法是什么、环境背景是什么、素材该是什么风格。**
> 只想先知道玩起来什么样，直接读这节，前面十节可以后补。
> 格子布局的权威版本在 `docs/03_四关设计.md` 第四节。

### 0. 重力是这游戏唯一的机制，不是机关之一

四关里每一关都有磁场区，而且它是画面里最大的一块彩色区域——不是偶尔出现的道具。
玩家所有判断都绕着一句话转：**我现在被往哪个方向拽。**
尖刺、坑、平台、可动平台都只是这条规则的应用，它们本身不带新规则。

所以：紫色和那个箭头要画得足够清楚。它是整个游戏最重要的一个视觉符号，比角色还重要——
角色画糊了玩家只是看不清自己，磁场画糊了玩家不知道该往哪走。

### 1. 玩家在一关里只做五件事

| 步 | 玩家做什么 | 你要画的东西 |
|---|---|---|
| 1 | 按 ← → 在地上走 | 地面砖，朝向玩家的那一面有 3px 高光边 |
| 2 | 按空格跳上 2 格高的台阶 | 台阶的侧壁 + 顶面 |
| 3 | 从台阶顶跨过 4 格宽的坑 | 坑里**什么都不画**，露出最暗的背景 |
| 4 | 走进紫色磁场，人被推向天花板 | 半透明紫场 + 往里漂的石粒 + 一个最亮的朝上箭头 |
| 5 | 沿着天花板走到发光的门 | 门洞；天花板内表面也必须有一条 3px 高光边 |

**全程只有两个动作：左右走、跳。** 没有攻击、没有道具、没有血量、没有敌人、没有计分。
玩家只有一种死法：掉进坑里。所以也不需要"受伤"的素材。

### 2. 环境背景：地心洞穴的一条间隙

- **这是一条纵向裂开的洞腔**：上下都是岩壁，左右是两根岩柱，玩家在缝里往上走。**没有天空、没有地平线、没有云、没有远景山。**
- 这个设定顺带把玩法解释了：上下都是石头，所以「倒着站天花板」不需要额外跟玩家解释一遍——他看得见头顶也是岩壁。
- 洞腔内部填 `#100D14`，上面叠 `#1C1720` 的岩体剪影，从裂缝的上下两端伸进来。**边缘必须是不规则的**，画成方框就变成房间，不是洞穴。
- 纵深只有四档明度：`#100D14` 洞腔 → `#1C1720` 远景岩体 → `#2E2530` 砖块 → `#4A3B45` + `#6B5560` 能站的表面。
- **动态只有一个：磁场里漂移的石粒。** 其他一律静止——不画光源、光晕、阴影渐变、雾、熔岩、水滴、飘尘、背景视差。

### 3. 风格：像素 Q 版，一个方块最多三档色

「像素风」「Q 版」这两个词单独都不够用，下面是可验证的判据：

| 判据 | 值 |
|---|---|
| 1 个美术像素 = 1 个屏幕像素 | 不做「伪像素」（先画大再缩小） |
| 角色头身比 | **2 头身**：头 16×14 + 身 14×12 = 28 高，宽 20 |
| 角色脸 | 两只 **2×3** 竖点眼睛，中距 6px，**不画嘴** |
| 一个 32×32 方块内最多 3 档明度 | 底色 + 亮面 + 描边，第四档开始就是噪音 |
| 外露的角 | 切 **2px** 斜角（Q 版最省钱的信号） |
| 角色描边 | 1px，色值以实际素材为准（11/2 交付版是黑） |
| 地形描边 | **不描**，靠明度差分离（1px 黑边在暗背景里等于消失） |
| 半透明 | 只允许两处：磁场场体 0.30 上限、石粒 0.55 |
| 动态 | **只有磁场里的石粒会动**，其余全静止 |

**为什么定这么严**：640×360 在 1080p 上是 3 倍整数放大，一个美术像素会变成 3×3 的方块。
细节多画一档，投影到墙上就是一团噪点；而且 8 天里细节越多越难统一，两个人画出来会像两个游戏。

**Q 版不等于加点细节。** 恰恰相反：Q 版是把形状做圆、比例拉成 2 头身、去掉一切装饰。20×28 这个尺寸上，加细节只会让它变成一团青色噪点，而不会让它更可爱。
