## 为什么统一 GDScript

| 原因 | 具体 |
|---|---|
| **版本必须统一** | C# 要用 Mono 版编辑器。**标准版打开带 `.cs` 的工程会直接报"缺少 C# 支持"，工程跑不起来。** 所以不存在"某人写 C#、其他人写 GDScript"，只能全队一个语言 |
| 装机成本 | 走 C# 要六个人今晚全部重装（Mono 编辑器 + .NET 8 SDK + 另一套导出模板），一个人漏装就出不了包 |
| 网页版 | C# 的 Web 导出基本不可用，而网页版是路演投票要用的（评委点开就能玩） |
| 学习成本低 | GDScript 语法接近 Python；而且 Godot 的节点 / 场景 / signal 这套，用 C# 也一样要从头学 |

> 会 C# 的看 `docs/09_CSharp到GDScript速查.md`，一页。

## 怎么跑起来

1. 装好 Godot 与 Git，配完 `git config`（`docs/工程规范.md` §5.0）
2. **配 SSH 并以 SSH 地址克隆**：`git clone git@github.com:jmx2033/GRAVSWITCH.git`
   路径用纯英文、不要中文和空格（推荐 `D:\git\GRAVSWITCH`）
3. **clone 完立刻装一次提交钩子**：`bash Tools/ci/install-hooks.sh`
   装完提交信息格式写错，本地当场被拦，报错里会写正确格式。**不读 418 行规范也能守规矩。**
4. **不要把项目放在 OneDrive / 坚果云 / 百度网盘同步目录里**——云同步会和 `.godot/` 打架
5. 双击 `project.godot`，Godot 会打开工程
6. F5 运行

> 工程由珈百璃先建好推上来，其他人**等推上去再 clone**。各自先 clone 会生成不同的 `.godot/`，之后很麻烦。

## 怎么出包

- **先确认导出模板已下载**（这是第一次出包唯一会卡住的地方，报错长这样："找不到导出模板"）
- Windows：`项目 > 导出 > Windows Desktop > 导出项目`，输出到 `build/win/`
- 拷贝给别人时**整个目录一起打包**，只发 exe 会缺 `pck`
- 出包用普通终端，不要在受限沙箱里跑

### 导出面板底部有三个按钮，只有中间那个能出 exe

| 按钮 | 产出 | 双击能跑吗 |
|---|---|---|
| **导出项目** | `xxx.exe` + `xxx.pck` | ✅ **要的是这个** |
| 导出 PCK/ZIP | 一个 `.pck` 或 `.zip` 资源包 | ❌ 没有引擎本体，只是素材打包 |
| 导出全部 | 所有预设各导一次 | 预设只建了一个时等同第一个 |

**怎么一眼认出点错了**：弹出的保存框里如果出现「**使用调试导出**」和「**导出为补丁**」两个复选框，文件类型是 `*.zip, *.pck`，那就是 PCK/ZIP 框，不是出 exe。「导出项目」弹的框文件类型是 `*.exe`。

### 预设里「导出路径」为空会白点一次

`export_presets.cfg` 里 `export_path=""` 时点「导出项目」，Godot 会先弹一次保存框让你选 `.exe` 存哪。这一次是对的框，选好之后路径会写回预设，下次不再问。建议第一次就填 `build/win/游戏名.exe`（相对工程根目录）。

**别导到工程根目录**。根目录已经有 `.gitignore` 挡 `*.exe` / `*.pck`，不会误提交，但文件会和 `project.godot`、场景混在一起，后面分不清哪个是要发出去的那份。

### 导出成功后目录里应该有三个文件

| 文件 | 是什么 | 大小（空工程） |
|---|---|---|
| `名字.exe` | 引擎本体 + 你的项目 | 约 100 MB |
| `名字.pck` | 你的场景、脚本、素材 | 约 7 KB |
| `名字.console.exe` | 同一份程序，但带控制台窗口，用来打日志 | 约 90 KB |

**exe 里不含你的素材，素材全在 pck 里。** 发给别人必须两个一起，少一个对方打不开。空工程的 pck 只有几 KB，正式工程会涨到几 MB。

### 怎么自证这次导出是成功的

双击 exe 能开窗口只是第一步，更硬的证据是跑控制台版：

```
名字.console.exe --quit-after 120
```

它会打印几行然后自己退出。看这两行：

```
Godot Engine v4.7.2.stable.official.xxxxxxx
OpenGL API 3.3.0 ... - Compatibility - Using Device: ...
```

- 第一行版本不是 `4.7.2.stable` → 模板装错版本了
- 第二行不是 `Compatibility` → 建工程时渲染器选错了，11/8 网页版做不出来

这两行对今晚的验收有用：六个人里谁渲染器选错，跑这一行当场就露出来，不用等到出网页版那天才发现。

## 交付形态：exe 为准，网页版是加分

| | 地位 | 说明 |
|---|---|---|
| **Windows exe** | **主交付，必须有** | 打包成 zip（只发 exe 会缺 `.pck`），传蓝奏云或群文件，链接填进官网 |
| **Web 版** | 加分，导得出来就发 | 同一份工程，导出面板里多建一个 `Web` 预设。**不是重做一版游戏，是再点一次导出** |

**网页版的存在理由只有一个：路演是"全体开发者投票"，点开就能玩的链接，转化率明显高于下载一个 zip。** 但它不是交付义务。

**砍的条件（写死）**：11/8 10:00 代码冻结时，Web 还导不出来 → 直接砍掉，只交 exe。砍掉不影响主体评分，纠结它影响。

### 网页版的两个坑（真做的时候）

1. 导出预设里**关掉 Thread Support**（多线程）。GitHub Pages 不支持 COOP/COEP 响应头，开着会白屏
2. **不能双击 `index.html` 打开**，`file://` 协议会被浏览器拦。必须走 http（本地起个静态服务，或直接放 Pages）

### 为什么渲染器仍然选兼容

选 `兼容（Compatibility）` 不是为了网页版，**它本身就是 2D 像素项目的正确选择**：启动快、低端机跑得动，Forward+ 的 3D 能力这里一条都用不上。网页版只是顺带得到的能力。

反过来，选了 Forward+ 再想加网页版，要换渲染器并重查所有场景——那才是 11/8 来不及的事。
