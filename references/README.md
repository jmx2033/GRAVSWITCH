# references —— 前置验证材料，不参与构建

这里的文件**不是交付物，也不要拖进 Unity 场景**。

| 文件 | 是什么 | 怎么用 |
|---|---|---|
| `demo.html` | 个人前置浏览器原型（V0.3.1，单文件零依赖） | **数值与公式的标尺**。JS 不能移植到 C#，但参数可直接抄，见 `docs/04_数值表.md` |
| `设计文档_v0.1.md` | 原始方案（18 项强化 + 首领 + 局外 + 10 分钟） | **仅作历史对照**，本次不做 |
| `设计文档_v0.2_三分钟沙盒.md` | 3 分钟沙盒版 | 历史快照 |
| `设计文档_v0.3_形变优先.md` | 现行设计基线 | 设计问题以这份为准 |

## 三份文档谁说了算（冲突时按这个顺序，不要临场吵）

| 争的是什么 | 听谁的 | 备注 |
|---|---|---|
| 做不做、P 编号、范围 | `docs/00_范围与不做清单.md` | 它自称"唯一权威范围"，本页不与之争 |
| 具体数值（速度 / 血量 / 刃形 / 经验） | `docs/04_数值表.md` | 它的来源就是这里的 `demo.html`，两者冲突时以 `demo.html` 实际代码为准 |
| 机制、表现、为什么这么设计 | `设计文档_v0.3_形变优先.md` | 但它**不决定范围** |
| 怎么写、怎么提交、怎么放文件 | `docs/工程规范.md` | 与设计无关 |

**一个必须说清的差异：** v0.3 是个人项目「阶段 0 手感沙盒」的口径——**6 张正式强化 + 3 张校准卡**；本次 9 天实训按 `00_范围与不做清单.md` 执行，**只有 4 张卡（扩容 / 伸展 / 超频 / 余波），且不做校准卡**。这不是文档打脸，是范围被主动砍过；卡池规模一律以 00 为准。

## 为什么留着它们

答辩时可以一句话带过：**"我们先做浏览器原型验证手感，再迁到 Unity。"**
这是成熟流程，不是绕路——但**不要当主线讲**，评审看的是游戏能不能玩。
